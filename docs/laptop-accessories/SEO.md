# Accessory SEO and discovery

Canonical structure: `/laptop-accessories/{categorySlug}/{productSlug}`, HTTPS apex. One canonical for all originality/condition offers. Generic `/product/{id}` permanently redirects; its metadata also resolves the accessory canonical. Normal Product and Laptop identity remain unchanged.

Shared `publicProductHref` resolves cards, search, cart, wishlist, Telegram and IndexNow projections. Accessories are excluded from unrelated generic catalog defaults; global search may include part number, model and compatibility terms. Dedicated pages expose category/brand/condition/authenticity/stock/model filters as client state, not extra indexable URLs.

Metadata uses actual names, part/model/summary and optional Admin SEO fields. SSR Product and active Offer schema uses IRR = displayed Toman ×10, accurate inventory and New/Used condition. No fabricated ratings or affiliation. BreadcrumbList uses existing helper. Unknown testing/compatibility is not filled in.

Empty main/category routes are noindex/follow; sitemap excludes empty categories/main until published inventory exists. Hidden accessories are excluded. Accessory canonical paths are accepted by the existing IndexNow single-page protocol; no bulk submission, no fake inventory submissions. Existing failure-isolated scheduling remains.

Laptop model pages query real compatibility relations and display published active-offer accessories. Accessory pages link only to existing matching public Laptop model groups; an unavailable public page is shown as text rather than a guessed/broken URL.

Homepage content, H1, metadata, canonical, Hero and image timing remain unchanged. Only the explicitly requested Laptop navigation entry gains an accessible nested menu. Exact test exceptions reverse that navigation change and central ProductSlider URL resolution before checking the original frozen digest; the original digest is not replaced.

Preview/live canonical, responsive and discoverability verification remain release gates. No field performance claims are made by unit tests or local build.
